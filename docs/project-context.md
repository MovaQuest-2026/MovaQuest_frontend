# MovaQuest: контекст, мета, стан і проблеми

Стан на 19.11.2026, гілка `feat/video-gap-fill` (коміт `0e29f0f` і зміни після нього). Документ для аналізу проєкту й для старту нових чатів: що це за продукт, куди він іде, що вже працює, що болить. Правила коду й архітектури детально описані в [CLAUDE.md](../CLAUDE.md), вимоги до бекенду в [backend-requirements.md](backend-requirements.md) і [backend-plan.md](backend-plan.md), додавання відео в [adding-videos.md](adding-videos.md).

Позначки: **[факт]** перевірено в коді чи даних; **[перевірити]** стан невідомий або міг змінитися; **[питання]** рішення ще не ухвалене.

## 1. Коротко

MovaQuest (робоча назва) — mobile-first веб-застосунок для того, щоб освіжити іспанську перед поїздкою. Користувач гортає стрічку коротких вертикальних відео (як у TikTok). У певний момент відео стає на паузу, і треба вголос сказати слово, яке прозвучить далі, відповісти на запитання або повторити почуте слово. Голос розпізнає бекенд, вердикт рахує фронт. Неправильно — ще спроба з підказкою, завжди можна пропустити.

Ключова ідея: не урок і не тест, а звична стрічка коротких відео, в якій треба говорити.

## 2. Контекст

### Аудиторія
- 18–30 років, їдуть в іншу країну на деякий час (Іспанія).
- Мова вже є, її треба освіжити, а не вчити з нуля.
- Звикли до TikTok / Reels: вертикальне відео, свайп, лайк, коментарі.

### Мови
- Мова вивчення: іспанська (Іспанія).
- Мови інтерфейсу: en (за замовчуванням), uk, es.
- Переклад контенту (субтитри, переклад слова): en, uk.

### Історія концепції
1. **Гра на Phaser** (вересень 2026): місто, квести, діалоги. Гілка `legacy/phaser-game`, промпти в `prompts/L*.md`.
2. **Розгалужені відеоісторії** з вибором correct / wrong / unclear. Гілка `legacy/interactive-video`.
3. **Поточна:** стрічка коротких відео з паузами для відповіді голосом (`feat/video-gap-fill`).

Окремо в застосунку є клікабельний прототип ширшого продукту (бібліотека, розмовна практика, тарифи) на `/prototype` (`src/prototype/`). Це макет для обговорення, не робочий функціонал.

### Команда й процес
- Розробник фронтенду (він же продукт), окремий бекенд-розробник (репозиторій `MovaQuest-2026/backend`), дизайнерка, яка дає фідбек по UX через чат зі скриншотами.
- Код значною мірою пишеться з AI-асистентом. Правила для нього в CLAUDE.md, «готово» = `npm run lint` + `npm run build` без помилок і ручна перевірка на 360×800.

## 3. Мета

### Продуктова мета MVP
Перевірити, чи людям цікаво й корисно практикувати мову, говорячи вголос у форматі стрічки коротких відео: чи доходять до кінця відео, чи відповідають голосом, чи повертаються.

**[питання]** Конкретних цільових метрик (retention, частка відповідей голосом, кількість відео на сесію) у репозиторії не зафіксовано. Події для них уже відправляються в PostHog (див. §4.6), але пороги успіху не визначені.

### Що має бути правдою для запуску
- Відео стартує одразу, без реєстрації й без екранів «натисни, щоб почати».
- Пауза стоїть точно: користувач розуміє, що від нього хочуть, і чує правильну відповідь після спроби.
- Розпізнавання голосу працює на окремих словах на Android Chrome.
- Прогрес не губиться: акаунт, синхронізація з бекендом.
- Стрічка не закінчується (зроблено по колу) і виглядає «живою» (лічильники, коментарі).

## 4. Поточний стан

### 4.1 Стек та інфраструктура [факт]
- Фронт: Vite 8, React 18, TypeScript 6, react-router-dom 7, Zustand 5 (persist), react-i18next, PostHog. Tailwind лише для лендінгу. Без ігрового рушія.
- Деплой фронту: Vercel, `https://mova-quest-frontend.vercel.app`. `/api/*` проксіюється на бекенд (vercel.json; локально `server.proxy` у vite.config.ts).
- Бекенд: FastAPI (шаблон FastAPI Boilerplate) на безкоштовному Render, `https://backend-hb2j.onrender.com`, Postgres. Сесії в cookie, CSRF для змінних запитів.
- Розпізнавання мови: `POST /api/v1/transcription` → Deepgram Nova-3 (es) з підказками очікуваної відповіді. Бекенд віддає лише транскрипт, вердикт рахує `matchAnswer()` на фронті.
- Відео й уроки живуть у фронтенді: `public/clips/<lessonId>/` (≈33 МБ) і JSON у `src/mocks/lessons/`. Оригінали в `media/source/` (≈17 МБ). Репозиторій ≈71 МБ.
- Кожна інтеграція має мок-перемикач у `.env` (`VITE_MOCK_SPEECH`, `VITE_MOCK_SOCIAL`, `VITE_MOCK_PROFILE`, `VITE_MOCK_PROGRESS`, `VITE_SOCIAL_SEED`). Див. `.env.example`.

### 4.2 Що вміє застосунок [факт]
**Плеєр і стрічка**
- Стрічка вертикальних відео: свайп угору/вниз, коліщатко й ↑/↓ на десктопі; йде по колу. Сусідні уроки підвантажуються наперед.
- Відео стартує одразу; без жесту користувача — без звуку з кнопкою «Увімкнути звук».
- Паузи трьох типів: `nextWord` (сказати наступне слово), `answer` (відповісти на запитання), `repeat` (повторити щойно почуте слово). Логіка — автомат `gapMachine.ts` без React, з юніт-тестами.
- Відповідь голосом (запис вмикається сам, якщо дозвіл на мікрофон уже є) або текстом. Спроби, підказка (перша літера), «Пропустити», «Ще раз» (відмотує на 4 с).
- Навігація: повзунок з мітками слів (зелені — сказано, червоні — ні), стрілки «попереднє / наступне слово», дотик будь-де — пауза, подвійний дотик — лайк, затиснутий край відео — перемотка (вперед зупиняється перед нерозв'язаним словом).
- Повтор уже пройденого слова з кнопки над відео (результат не погіршується).
- Субтитри будь-якою комбінацією es / en / uk; швидкість 0.5–1.5× (крім TikTok-плеєра).
- Підсумок уроку — модальне вікно поверх відео з рахунком і списком слів.
- Соцфункції: лайк, збереження, коментарі, поширення, лічильники. Лайк, збереження й коментар потребують акаунта.

**Акаунт і профіль**
- Вхід необов'язковий. Email + пароль і Google (redirect-flow бекенду). Після першого входу — онбординг (мова інтерфейсу, рівень, мета поїздки).
- Профіль і прогрес (пройдені уроки, вивчені слова, точність, незавершені уроки) зберігаються на бекенді й синхронізуються; є офлайн-кеш на пристрої.
- Профіль: налаштування згруповані (Навчання / Відео / Вигляд / Мікрофон), тема (системна / світла / темна) картками з мініатюрою, субтитри мультиселектом, швидкість повзунком, тест мікрофона.

**Інше**
- Лендінг на `/`, «Серії» (`/lessons`) з фільтром «Усі / Збережені».
- Аналітика PostHog (вмикається ключем `VITE_POSTHOG_KEY`): `lesson_started`, `gap_reached`, `answer_checked`, `hint_shown`, `gap_resolved`, `lesson_completed`, `mic_denied`, лайк / збереження / поширення / коментарі.

### 4.4 Якість [факт]
- `npm run lint`, `npm run build` проходять; 152 юніт-тести (vitest): автомат пауз, перевірка відповідей, протокол TikTok, дані й медіа уроків, API-шари, синхронізація прогресу.
- Тести перевіряють, що видимий у момент паузи субтитр-оригінал не містить відповіді; переклади субтитрів перевіряються вручну.
- Ручна перевірка на 360×800; основна платформа — Android Chrome. iOS Safari не тестується.

### 4.5 Останні зміни (правки дизайнерки, 19.11.2026)
- Шрек: паузи після слова (`repeat`), бо раніше питали слово до того, як воно прозвучало.
- Стрілки слів переходять саме на слово, не перескакують близькі.
- Пауза дотиком по всьому відео; ±5 с дотиком прибрано, замість цього перемотка затисканням краю.
- Помітніші кнопки CC і швидкості; точки прогресу не виштовхують кнопки за край.
- Компактний список слів у підсумку.
- Профіль: одна кнопка входу, групи налаштувань, нові контроли (тема, субтитри, швидкість).
- Плейсхолдер-відео: музика замість писку.
- Стрічка по колу.

## 5. Проблеми й ризики

### Продукт і контент
1. **Права на відео.** Більшість справжніх кліпів — фрагменти чужих серіалів, мультфільмів і роликів. Для MVP і демо це прийнятно, для публічного запуску — юридичний ризик. **[питання]** Звідки брати контент далі: власні зйомки, ліцензії, UGC, TikTok Embed (вбудований плеєр уже підтримується)?
2. **Мало контенту і він ручний.** 12 уроків, кожну паузу й субтитр ставлять вручну по секундах. Помилки таймінгу одразу ламають досвід (як було в Шреку). Масштабувати так важко.
3. **Три плейсхолдер-відео** без справжнього відео (текст на фоні) виглядають як заглушки в стрічці.
4. **Накрутка соцлічильників.** До справжніх лайків і коментарів додається мок-база (`VITE_SOCIAL_SEED=true`), щоб стрічка виглядала живою. Перед публічним запуском треба вирішити, чи це прийнятно.
5. **Атрибуція музики.** Трек «And So It Begins» (Artificial.Music) вимагає вказати автора; зараз це лише в `media/music/CREDITS.md`, у застосунку немає.
6. **Рейтинг.** Є запит, немає рішення ні по UX (варіант — вкладка в профілі), ні по бекенду. **[питання]**
7. **Немає цільових метрик**, хоча події вже збираються (див. §3).

### Технічні
1. **Безкоштовний Render засинає.** Перший запит після простою — довгий холодний старт; фронт «будить» сервер (`wakeBackend()`), але перша відповідь голосом після простою може бути повільною.
2. **Google-вхід залежить від налаштувань бекенду** (`OAUTH_REDIRECT_BASE_URL`, redirect URI у Google Cloud). На 17.11 він не працював через `invalid_state`. **[перевірити]** чи виправлено.
3. **Розпізнавання окремих слів.** Deepgram на одному слові з шумом може помилятися; є підказки (`hint`), нечітке порівняння в `matchAnswer()` і стан `unclear`. Якість на реальних користувачах не виміряна. **[перевірити]**
4. **Відео в git.** Репозиторій ~71 МБ і росте з кожним кліпом; для десятків уроків знадобиться CDN / об'єктне сховище.
5. **iOS не тестується.** Android-only API не використовуються, але поведінка автозапуску зі звуком, мікрофона й жестів на Safari невідома.
6. **Жести на телефоні.** Затискання для перемотки, пауза дотиком і свайп стрічки перевірені синтетичними подіями в браузері, на живому телефоні — ні. **[перевірити]**

## 6. Відкриті питання
- Цільові метрики MVP і як їх дивитися в PostHog.
- Джерело й ліцензування контенту; хто й як ставить паузи (інструмент для розмітки?).
- Рейтинг / гейміфікація: що саме рахуємо і де показуємо.
- Залишати чи прибирати накрутку лічильників.
- Коли переходити з безкоштовного Render і де зберігати відео.
- Чи потрібен iOS на старті.
